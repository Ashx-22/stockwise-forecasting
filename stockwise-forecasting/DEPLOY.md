# Deploying Stockwise

Two pieces to deploy: the **frontend** (Vercel) and, only if you want the "Live from API" badge and a
callable forecasting endpoint, the **backend** (Render, Railway, Fly.io, or any Docker host).

## Part 1: Frontend only (works standalone, no backend needed)

The site is fully static-data driven — `frontend/public/data/*.json` is generated once by the pipeline and
committed (or regenerated by CI). You do not need a live backend for the site to work.

1. Generate the data locally first, so it's committed to the repo:
   ```bash
   cd backend
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements-dev.txt
   python -m stockwise.pipeline
   ```
   Check that `frontend/public/data/*.json` now has real content (`git status` should show new/changed
   files there).
2. Push the whole repository to GitHub.
3. On vercel.com: **Add New → Project**, import the repo.
4. Set **Root Directory** to `frontend` (Vercel asks this during import, or set it later under
   Settings → General). Framework preset: Next.js (auto-detected). Leave build settings as default.
5. Deploy. Your site is live at `https://your-project.vercel.app`.

That's it for a fully working site. Skip to Part 3 if you don't need the live API.

## Part 2: Backend API (optional, for the "Live from API" badge)

### Option A: Render (simplest)

1. Push the repo to GitHub if you haven't.
2. On render.com: **New → Web Service**, connect the repo.
3. Set:
   - **Root Directory:** `backend`
   - **Environment:** Docker (Render detects the `Dockerfile`)
   - **Instance type:** the free tier works but sleeps after inactivity, so the first request after a
     while will be slow (the model retrains at build time in the Dockerfile, so no separate step is needed)
4. Deploy. Note the URL, e.g. `https://stockwise-api.onrender.com`.
5. Check it: open `https://stockwise-api.onrender.com/health` — should return `{"status":"ok",...}`.

### Option B: Railway / Fly.io / any Docker host

`backend/Dockerfile` is self-contained: it installs dependencies, trains the model at build time, and
starts `uvicorn`. Any host that builds from a Dockerfile in a subdirectory works the same way — point it
at `backend/Dockerfile` and it needs no other configuration. Set `PORT` if your host requires a specific
one (the Dockerfile already reads `$PORT`, defaulting to 8000).

### Connect the frontend to it

Back in Vercel: **Settings → Environment Variables**, add:
```
NEXT_PUBLIC_API_URL = https://stockwise-api.onrender.com
```
Redeploy (Vercel → Deployments → latest → Redeploy) for the variable to take effect. Open the site, go to
the forecast explorer, and check for the "Live from API" badge after selecting a series.

**CORS:** the API allows all origins by default (`ALLOWED_ORIGINS` env var, default `*`). To restrict it to
just your site, set `ALLOWED_ORIGINS=https://your-project.vercel.app` on the backend host.

## Part 3: Keep the data current

The committed JSON is a snapshot. To refresh it:
```bash
cd backend && python -m stockwise.pipeline
git add frontend/public/data
git commit -m "Refresh forecast data"
git push
```
Vercel redeploys automatically on push. If you're running the live API too, redeploy it as well so both
sides reflect the same model (the CI workflow in `.github/workflows/ci.yml` only tests — it does not
auto-deploy; wire up your host's own GitHub integration for that, which both Vercel and Render do by
default on push).

## Troubleshooting

| Symptom | Fix |
|---|---|
| Vercel build fails on `frontend/public/data` missing | Run the pipeline locally and commit the JSON before pushing, or add a build step that runs it (see below) |
| Site loads but shows "Could not load the forecast data" | `public/data/*.json` is missing or empty; regenerate and commit it |
| "Live from API" badge never appears | Check `NEXT_PUBLIC_API_URL` is set in Vercel and you redeployed after setting it; check `/health` on the API directly |
| Render build times out | The free tier build can be slow on first deploy; it should still finish within Render's limit (the pipeline itself takes about a minute) |
| CORS error in the browser console | Check `ALLOWED_ORIGINS` on the backend includes your exact Vercel domain (no trailing slash) |

### Optional: regenerate data automatically on every deploy

Add a Vercel build command override (Settings → General → Build Command) if you'd rather not commit the
JSON:
```
cd ../backend && pip install -r requirements.txt && python -m stockwise.pipeline && cd ../frontend && next build
```
This needs Python available in the Vercel build image, which is not guaranteed on all plans — committing
the generated JSON (Part 3) is the more reliable approach and is what this project assumes by default.
